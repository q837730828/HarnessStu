# HarnessStu — Project Architecture

> Generated by `architecture-mapper` subagent.

## 1. Project Overview

**HarnessStu** is a small Java agent harness built for learning Claude Code–style architecture. It implements the core agentic loop:

```
user prompt → model response → tool call → local execution → observation → model continues → final answer
```

- **Language**: Java 8 compatible
- **Build**: Maven
- **JSON**: Jackson
- **Package**: `com.ahi.harness`
- **Source root**: `src/main/java/com/ahi/harness/`
- **Config root**: `.harness/` (settings, permissions, subagents, sessions, compactions)
- **External tool protocols**: stdio JSON-RPC (MCP-style) and Streamable HTTP

## 4. Runtime Sequence (AgentLoop.run)

```
AgentLoop.run(conversation, userInput)
 │
 ├── RunRecorder.beginRun() → AgentRun(CREATED → RUNNING)
 ├── hooks.emit("UserPromptSubmit", userInput)
 ├── conversation.addUser(userInput)
 ├── sessionStore.appendMessage(...)
 │
 └── for step = 1..maxSteps:
      │
      ├── check timeout + durable cancellation request
      │
      ├── IF conversation.size > compactMaxMessages
      │    └── compactConversation()
      │         ├── compactionArchiveStore.archive(older messages)
      │         └── conversation.compact(keepRecent, archivePath)
      │
      ├── warnIfContextLarge(conversation)
      │    └── 220K warning / 256K error
      │
      ├── hooks.emit("PreModelCall")
      ├── RunRecorder.startStep(MODEL_CALL)
      ├── response = model.generate(conversation, tools)
      │    └── DeepSeekClient → HTTP POST to DeepSeek API
      ├── hooks.emit("PostModelCall")
      ├── check timeout + durable cancellation request again
      │
      ├── conversation.addAssistant(content, reasoning, toolCalls)
      ├── sessionStore.appendMessage(...)
      │
      ├── IF no toolCalls → hooks.emit("Stop") → RETURN
      │
      └── FOR each ToolCall:
           ├── check timeout + durable cancellation request
           ├── RunRecorder.startStep(GUARDRAIL)
           ├── hooks.emit("PreToolUse", detail)  ← can block
           ├── PermissionDecision = permissions.check(call)
           │    └── IF requiresApproval → permissionPrompter.resolve()
           ├── IF allowed → tool.execute(args) → ToolResult
           │    └── ToolResult.toObservation()
           ├── ELSE → ToolResult.failure("Permission denied: ...")
           ├── conversation.addToolResult(id, observation)
           ├── sessionStore.appendMessage(...)
           └── hooks.emit("PostToolUse")
           └── RunRecorder.checkpoint(messages)
```

The protocol event stream is written separately from console Trace output. A
Run directory contains the latest Run snapshot plus append-only Step, Event,
provider-neutral Message/Part, Artifact, Interrupt, TraceSpan, and ProtocolError
histories. Events and checkpoints carry `traceId/spanId` correlation directly.
Checkpoints contain complete provider-facing Message snapshots; compaction
archives only preserve context removed from the active model window.

## 5. Key Design Decisions

### 5.1 Java 8 Compatibility
All code uses Java 8 language features only. The Maven runtime may use JDK 8, so no lambdas or streams where they might differ.

### 5.2 No Framework Magic
No Spring Boot, no LangChain-style abstractions. The harness wires its own dependencies explicitly in `Main.java`. Each runtime concept (model, tools, permissions, sessions, hooks) has an explicit interface.

### 5.3 Logging for Learning
Logs are designed to help a learner understand the runtime:
- Full HTTP request/response JSON (optional, via `logJsonBodies`)
- Tool arguments at invocation time
- Permission decisions (allowed/denied + reason)
- Hook lifecycle events
- Observations sent back to the model
- Context size warnings
- Diff before file writes
- Validation command results

`reasoning_content` is not logged raw — only a placeholder and character count.

### 5.4 Permission Modes
Three modes that control what tools can mutate state:
- **strict** — uses configured allow/deny lists, no prompting
- **ask** — prompts user for `edit_file`, `bash`, `subagent_write`, and non-allowlisted external tools; user can persist choices to `.harness/permissions.json`
- **danger-full-access** — allows bash commands after blocked-token and shell-control checks

### 5.5 Pluggable Model Interface
`ModelClient` is a single-method interface: `generate(Conversation, ToolRegistry) → ModelResponse`. The only implementation is `DeepSeekClient` using OpenAI-compatible chat completion API.

### 5.6 External Tool Ecosystem (MVP5–6)
Tools can come from three sources:
1. **Built-in tools** — Java implementations directly in the harness
2. **Simple stdio** — external processes that read `{"args":[...]}` on stdin
3. **MCP stdio/HTTP** — Model Context Protocol using JSON-RPC, either over stdio or Streamable HTTP

`McpServerManager` caches and manages the lifecycle of all MCP client connections.

### 5.7 Subagent System (MVP8–9)
Subagents are isolated read-only agents loaded from `.harness/agents/*.md`. They use frontmatter + Markdown:
- Allowed tools: `list_files`, `read_file`, `grep` only
- `max_steps`: clamped to 1..16
- Configurable memory, permission mode, model, and MCP servers
- Built-in roles: `explorer`, `reviewer`; project can define more via `subagent_write`

### 5.8 Lifecycle Hooks (MVP12)
Hooks are external commands or scripts triggered on lifecycle events:
- Configured in `.harness/settings.json`
- Can be blocking (nonzero exit blocks the tool call)
- Receive `HARNESS_HOOK_EVENT` and `HARNESS_HOOK_DETAIL` env vars
- Can be scoped to specific tools
- Supported script extensions: `.ps1`, `.cmd`, `.bat`, `.py`

### 5.9 Traceable Compaction (MVP13)
When compaction triggers, the harness writes archived messages to `.harness/compactions/*.jsonl` before removing them from active context. The summary stores the archive path, message count, and a short index.

### 5.10 Slash Commands
Local commands handled by `SlashCommandHandler` without sending to the model include
`/runs`, `/run`, `/run/events`, `/run/cancel`, `/checkpoint/load`, `/compact`,
`/resume`, `/mcp/status`, and `/mcp/reload`.

## 6. Configuration Files

|---|---|---|
| `.harness/settings.json` | JSON | Model endpoint, hooks, permission mode, allowlists, compaction thresholds, external tool servers |

| `.harness/sessions/*.jsonl` | JSONL | Resumable conversation message logs |
| `.harness/compactions/*.jsonl` | JSONL | Traceable compaction archives |
| `.harness/runtime/` | JSON + JSONL | Explicit protocol resources and recoverable message checkpoints |
| `.harness/agents/*.md` | Markdown + Frontmatter | Project-level subagent definitions |
| `.harness/todos/current.json` | JSON | Active todo planning state (set by `todo_write`) |
| `HARNESS.md` / `CLAUDE.md` / `AGENTS.md` | Markdown | Project memory injected into system prompt |
